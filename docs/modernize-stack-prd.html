PRD — PermaPages Modernization: Instant Pages on Arweave / AO / HyperBEAM

Task slug: modernize-stack · Created 2026-07-03 · Companion doc: modernize-stack-progress.html · Repo: /Users/tron/code/permapages (app in app/, Svelte 4 + Vite 5 + tinro)

Summary

PermaPages (v0.2.12) is a pre-AO permaweb app: page publishing registers Warp/SmartWeave contracts, state reads evaluate contracts client-side from genesis, the deploy path targets the dead Bundlr network, and every published page embeds the in-browser Tailwind CDN compiler. This work modernizes the stack to the mid-2026 ecosystem — plain data-item publishing via Wander dispatch() (Turbo bundling), AO reads via HyperBEAM patched HTTP GETs, ArNS via @ar.io/sdk 4.x — so all three "page" surfaces load instantly, and redesigns the five core screens.

Definition: "Arweave latest / AO latest / HyperBEAM"

  • Arweave latest: pages/posts as plain signed data items via window.arweaveWallet.dispatch() (Wander → Turbo, free <100KiB). Remove smartweave, warp-contracts(+plugin), arweave-account, arweave-wallet-connector, dead deps ardb/arweave-bundles/@verto/flex. Deploy script → permaweb-deploy.
  • AO latest: @permaweb/aoconnect ^0.0.98; STAMPs via @permaweb/stampjs ^1.0.4 (AO process). No dryrun on critical paths.
  • HyperBEAM: AO state reads via patched HTTP GETs on forward.computer (~process@1.0/compute), dryrun only as coded fallback for unpatched processes.

Goals in scope

  1. Zero client-side SmartWeave/Warp evaluation; warp deps deleted from package.json.
  2. Published-page template renders content with no JS and no runtime CSS compiler.
  3. ArNS screens work read-only on @ar.io/sdk 4.x; "point name at page" (ANT.setRecord) preserved (link-out fallback allowed).
  4. Dashboard/pages-list data loads via parallel single GETs.
  5. Redesign of home, connect dialog, dashboard, pages list, editor — each ≥4/5 on the taste rubric.
  6. npx vite build and npx vitest run green after every step.

Non-goals out of scope

  • No migration of already-published pages (immutable on Arweave).
  • No AO process spawned per page (no createAtomicAsset process-per-page from browser wallet). New pages are plain data items with existing Protocol: PermaPages-v0.5 tags.
  • No Svelte 5 / SvelteKit rewrite; no router change.
  • No in-app ArNS purchase/claim (pilot.ar.io + warp registry dead → link out to arns.arweave.net).
  • No @ardrive/turbo-sdk dependency (dispatch already routes through Turbo).
  • No arweave.app wallet (unmaintained connector); Wander only.
  • No new backend/cache service; must work from any ar.io gateway.

Constraints

  • Keep Svelte 4 + tinro hash routing. App must build with npx vite build, tests with npx vitest run, after every step.
  • Wallet flows stay on window.arweaveWallet with scopes exactly ACCESS_ADDRESS, SIGN_TRANSACTION, DISPATCH.
  • Frozen code: Wander arweaveWallet.encrypt/decrypt branches in load()/postTx() (services/arweave.js) — private-notes compatibility. Any diff there is a review flag.
  • Every dispatch() call site must be behind an explicit user action (no dispatch on mount/reactive).
  • No secrets/wallets committed; wallet.json stays untracked.
  • GraphQL discovery tags on published items unchanged (existing pages must keep listing).
